# Practice scenarios

Each brief is phrased vaguely, the way an evaluator would. The **trap** is what the 5-question
grill should surface in round 1 without prompting. A run passes when the trap shows up in the
grill, and ralph ends with `PASS OK`.

## 1. Tags

> "Let users tag notes and filter by tag."

Trap: tags unique per user or global; case sensitivity of names; N+1 on the list (`includes`).

## 2. LLM summary (GenAI, most likely)

> "Add an endpoint that summarizes a note with an LLM."

Trap: tests never hit the network (stub the `ruby_llm` client); provider timeout/error path;
summary cached or regenerated.

## 3. Structured extraction (GenAI)

> "Extract structured data from free text using AI."

Trap: malformed or wrong-shaped JSON from the model; validate against a schema, retry once or
fall back; a test for the bad-output path.

## 4. AI quota

> "Limit each user to N AI requests per day."

Trap: whose time zone defines "day"; race at the limit (DB constraint or transaction); what
the client sees when blocked (429?).

## 5. Reminder email

> "Send a reminder email when X happens."

Trap: synchronous vs ActiveJob; idempotency on retry; `assert_enqueued_with`.

## 6. Bug fix in an existing repo

> "Here's a bug: the list shows other users' records."

Trap: scoping to the current user; failing test before the fix. The grill should be 1–2
questions, not 5.

## 7. Search

> "Add search to notes."

Trap: LIKE vs full-text; escaping `%` and `_` in user input; pagination.

## 8. Paginated JSON API

> "Paginated JSON API for records."

Trap: cursor vs offset; stable sort order; the shape of an empty page.

# Greenfield scenarios (clean-context generation, 2026-09-27)

Generated by an agent with no access to existing projects (only `rails-agent-boilerplate/`).
Each starts from an empty app made by `bin/new-project`, so the variant router decision is part
of the exercise. Numbering continues from above.

## 9. Support ticket triage with an LLM

> "We get a lot of support emails. Use an LLM to categorise each incoming ticket and give it a priority so agents know what to pick up first."

- Variant signals: server-rendered app for internal agents, no API consumers → row 1, `main` (VARIANTS.md rule 2, simplest wins).
- Trap: fixed category enum (inclusion validation + DB check constraint) vs free text; invalid JSON / unknown category → save as `unclassified` or raise; sync vs async in v1 (sync, async as follow-up #10); LLM client: raw `Net::HTTP` vs a gem under "no new gems".
- Why it's likely: the canonical "structured LLM output into a Rails model" task.
- Pass: `SupportTicket` (body not null, category/priority enums with check constraints), `TicketClassifier` with an injected client, create form. Tests: model constraints (US-1); classifier with fake valid JSON (US-2); request POST shows category (US-3). Edge: malformed JSON / unknown category → `unclassified`, no exception.

## 10. Follow-up: make triage async and live-updating

> "Nice. Now classification is slow and sometimes the provider rate-limits us. Make it not block the form, and have the page update when the result lands."

- Variant signals: same app, still Hotwire → stays `main`; ADR-0001 revisit triggers don't fire.
- Trap: retry policy on 429/timeout (`retry_on` with backoff and max attempts; final `failed` state); idempotency (re-run must not reclassify); live update via `broadcasts_refreshes` vs targeted Turbo Stream, and stream name; whether a system test is in scope (no system test scaffolding in the boilerplate).
- Why it's likely: "now extend what you built" is the classic second half; jobs + rate limits + Hotwire in one.
- Pass: `ClassifyTicketJob` with `retry_on RateLimited, wait: :polynomially_longer, attempts: 3`, `status` column (`pending/classified/failed`, check constraint, default `pending`), `after_update_commit` broadcast. Tests: create enqueues the job (US-1); job success → `classified` (US-2); broadcast asserted (US-3). Edge: fake always raises `RateLimited`, retries exhausted → `failed`.

## 11. Summarisation JSON API for a mobile client

> "Our mobile app needs an endpoint where it sends a long article and gets back a short summary. Keep costs sane."

- Variant signals: "mobile app" consumer is a row-2 signal → `variant/api-spa`, which **does not exist** (`bin/new-project` exits "Unknown variant branch"). Expected move: generate `main`, add `Api::V1` controllers inheriting `ActionController::API`, record in ADR-0001 that row 2 matched but the variant was unavailable, and list it under Deviations in the profile.
- Trap: machine-client auth (bearer token with digested storage vs no auth for the demo); cost lever (cache by SHA-256 digest with unique index + max input length); error contract (422 bad input, 502/503 provider failure, JSON error shape); `/api/v1` versioning.
- Why it's likely: "GenAI endpoint for another client" is common and tests over-building around the router.
- Pass: `POST /api/v1/summaries`, `Summary` (unique `content_digest`, summary not null), `Summarizer` with injected client. Tests: valid → 201 (US-1); same input twice → client called once (US-2); bad/missing token → 401 (US-3). Edge: over-limit input → 422, client never called.

## 12. Streaming assistant reply in the browser

> "Add a small 'ask the assistant' box to our product page. Answers should appear as they're generated, like ChatGPT."

- Variant signals: "like ChatGPT" is interactivity, not a stated React/Vue requirement → `main`; say out loud why row 3 (inertia) doesn't apply (rule 1).
- Trap: transport (Turbo Streams over Action Cable from a job vs SSE/`ActionController::Live`; Solid Cable already configured); persist chunks vs final text only; testing streams (fake yields N chunks → N broadcasts + final text); partial answer when the stream errors mid-way.
- Why it's likely: streaming is the GenAI UX question evaluators like to probe.
- Pass: `Question`/`Answer` (FK, `status`), `AnswerStreamJob` iterating `client.stream` and broadcasting appends to `[question, :answer]`. Tests: submit enqueues job and renders `turbo_stream_from` (US-1); fake yields `["Hel","lo"]` → body `"Hello"`, 2 broadcasts (US-2); marked `complete` (US-3). Edge: raise after one chunk → partial kept, `errored`.

## 13. Versioned prompt templates

> "Product keeps tweaking the prompt we use to write product descriptions. Let them change it without a deploy, and let us know which prompt produced which description."

- Variant signals: internal admin screen → `main`.
- Trap: append-only versions (edit creates a row, never UPDATE); one active version per key (partial unique index `WHERE active`, activation in a transaction); safe interpolation (`format` with named keys, missing key = validation error; never ERB/`eval`: brakeman and prompt-injection trap); generations store `prompt_version_id` FK.
- Why it's likely: prompt management and traceability come up in every "LLMs in production" discussion.
- Pass: `PromptVersion` (key, version, body, active; unique `[key, version]`; partial unique `[key] WHERE active`), `activate!` in a transaction, `ProductDescription belongs_to :prompt_version`. Tests: new body → version N+1 (US-1); activate! deactivates previous (US-2); generation records the active version and renders the product name (US-3). Edge: `%{unknown}` → invalid, can't activate.

## 14. Tool/function calling: order-status assistant

> "Customers keep asking 'where is my order?'. Build an assistant endpoint that can answer using our order data."

- Variant signals: "endpoint" is ambiguous; unless an external/mobile consumer is named, rules 1–2 → `main`. Ask in the grill.
- Trap: tool allowlist and schema (only `lookup_order(order_number)`, arguments validated); authorisation (an LLM-chosen order number must be scoped to the current customer: the security trap); loop bound (max N tool rounds); not-found / not-yours answer that leaks nothing.
- Why it's likely: tool use is the hottest GenAI topic, and the security angle is easy to probe.
- Pass: `Order` (fixtures for two customers), `OrderAssistant` with a tool registry and dispatch loop over an injected client. Tests: scripted tool call then final text includes status (US-1); unknown tool → safe refusal, no dispatch (US-2); loop stops after 3 rounds (US-3). Edge: another customer's order → "not found", its data absent from the next prompt.

## 15. RAG-lite: answer questions from help articles

> "We have ~200 help-centre articles. Let users ask a question and get an answer grounded in those articles, with links to the sources."

- Variant signals: server-rendered, internal content → `main`.
- Trap: retrieval (pgvector needs an extension + `neighbor` gem vs PG full-text search vs `float[]` embeddings with cosine in Ruby, fine at 200 docs; ADR-worthy); when embeddings are computed (job on save vs rake backfill); grounding threshold (below it → "I don't know" without calling the LLM); citations list the retrieved article ids.
- Why it's likely: RAG is the default GenAI interview topic; "lite" fits the slot if infrastructure is avoided.
- Pass: `Article` (title, body, `embedding float[]`), `EmbedArticleJob`, `Retriever` (top-k cosine), `Answerer` returning `{text, sources}`. Tests: fake embedder ranks expected fixture first (US-1); prompt contains retrieved bodies and sources listed (US-2); save enqueues embed job (US-3). Edge: all scores below threshold → "don't know", LLM never called.

## 16. Deliberately ambiguous: "add AI to our recruiting app"

> "We have a small recruiting tool. Add some AI to help recruiters screen candidates faster."

- Variant signals: none → rule 2 → `main`; the router step shows you refuse to speculate (rule 1).
- Trap: the whole grill is scoping. Pick one job (summarise CV, score fit, or draft rejection); fairness guardrails (no protected attributes in the prompt, no auto-reject, human decides — make it a story); input as pasted text, not PDF upload; output shape (score 1–5 + rationale, stored and editable).
- Why it's likely: vague briefs are handed out on purpose to watch requirements gathering.
- Pass: 3–4 stories with explicit Out of Scope. `Application` (cv_text, job_description), `FitAssessment` (score 1–5 check constraint, rationale, `reviewed_by_human` default false). Tests: fake score + rationale stored (US-1); out-of-range score rejected (US-2); recruiter override sets `reviewed_by_human` (US-3). Edge: sensitive fields (e.g. `date_of_birth`) absent from the prompt the fake received.

## 17. Per-user AI usage budget with an alert email

> "We're getting surprised by our LLM bill. Put a limit on how much each user can use the AI feature and tell us when someone's close to it."

- Variant signals: server-rendered → `main`; attach to a trivial AI action (e.g. "rewrite this paragraph") built in the same ticket.
- Trap: unit (tokens from provider `usage` vs request count; daily vs monthly window); enforcement (pre-check + post-record, and the race: ledger with a sum query vs atomic `UPDATE ... WHERE used + n <= limit`); alert once per window at a threshold (unique index on `[user, period, threshold]`); over-limit response (flash vs 429).
- Why it's likely: cost control is a real production concern and pulls in mailers and concurrency naturally.
- Pass: `User`/`UsageEvent` (tokens not null, `> 0` check), `Budget` service, `BudgetMailer.threshold_reached` via `deliver_later`, `AlertLog` with the unique index. Tests: under budget records usage (US-1); over budget blocked, client not called (US-2); crossing 80% enqueues exactly one email (US-3). Edge: crossing 80% twice in a period → one email.

## 18. Guardrails and an eval: moderating user reviews

> "Users post product reviews. Before they go public, check them with AI for abuse and personal data, and show us how accurate the check is."

- Variant signals: server-rendered with a staff moderation queue → `main`.
- Trap: layering (cheap regex for emails/phones first, LLM only for abuse); fail-closed on LLM error (hold, never publish); what "accuracy" means in the slot (golden set in fixtures/YAML, eval over a deterministic fake reports precision/recall, threshold test); state machine `pending → published | held` with DB default and check constraint.
- Why it's likely: guardrails and evals are the "senior GenAI" differentiators, and this makes them concrete.
- Pass: `Review` status enum, `ReviewModerator` (PII regex + LLM verdict via injected client), `lib/tasks/eval.rake` + a golden YAML fixture. Tests: email in review → `held`, LLM not called (US-1); abusive → `held`, clean → `published` (US-2); eval over golden set ≥ threshold (US-3). Edge: client timeout → `held`.

## Boilerplate facts that affect these scenarios (verified 2026-09-27)

1. **Only `main` exists.** `rails-agent-boilerplate` has no other branches; VARIANTS.md marks
   `variant/api-spa` and `variant/inertia` as "candidate", and `bin/new-project` exits with
   `Unknown variant branch` for them. Row-2/row-3 briefs (#11, anything naming React) fall back
   to `main` with the mismatch recorded in ADR-0001 and the profile's Deviations. Rehearse it.
2. **No `minitest/mock`.** `Gemfile.lock` pins minitest 6.0.6, where `require "minitest/mock"`
   fails (mock was split out). There's no WebMock/VCR and no LLM client gem in the base
   Gemfile. Settle a fake-client injection pattern before the interview.
3. **System tests are listed as a gate but not scaffolded.** `test/` has no `system/` dir or
   `application_system_test_case.rb`; `config/ci.rb` has the system step commented out while
   the profile lists it as gate 2. `bin/importmap audit` needs the network, and `ralph/once.sh`
   needs the plan committed first.
